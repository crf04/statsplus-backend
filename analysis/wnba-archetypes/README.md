# WNBA scoring archetype analysis

This package builds an independent 2026 WNBA scoring taxonomy from observed
attempt volume and shot context. It does not reuse NBA cluster centers or mix
NBA and WNBA player distributions.

## Layout

- `scripts/wnba_archetypes_2026.py` — reproducible fetch, validation,
  clustering, and diagnostics pipeline.
- `wnba_archetypes_data/2026/` — cached PBP Stats player totals and raw shots.
- `wnba_archetypes_outputs/2026/` — working assignments, cluster profiles,
  cluster-count diagnostics, and possession-start audit.
- `docs/data-sources-2026.md` — source evaluation, licensing caveats, and
  recommended contextual data.

Cached provider inputs and generated outputs are intentionally excluded from
Git because this repository is public and upstream redistribution rights are
not established. They remain available locally and can be regenerated by the
pipeline.

## Archetype inputs

The model currently uses:

- FGA/min, 3PA/min, and FTA/min;
- rim, short-midrange, long-midrange, corner-three, and above-break-three FGA
  shares;
- second-chance FGA share;
- putback FGA share; and
- early-offense FGA share after live-ball turnovers and defensive rebounds.

The early-offense field is an explicitly labeled PBP proxy: a non-putback shot
within seven seconds of a possession starting after a live-ball turnover or a
missed/blocked field goal. It is not a Synergy transition label.

Shooting efficiency, height, impact metrics, injuries, home/away status, rest,
and betting markets are excluded from clustering. Height may be attached later
as a separate size label.

## Current result

The current snapshot contains 152 eligible players. Seven clusters are retained
because they provide the strongest current combination of separation, bootstrap
stability, usable group sizes, and basketball interpretability. The diagnostic
file preserves results for `k=4` through `k=12` so this choice can be reassessed
as the season sample changes.

Primary artifacts:

- `wnba_archetypes_outputs/2026/player_archetypes_working.csv`
- `wnba_archetypes_outputs/2026/cluster_profiles_working.csv`
- `wnba_archetypes_outputs/2026/cluster_diagnostics.csv`
- `wnba_archetypes_outputs/2026/possession_start_type_audit.csv`

## Seven scoring archetypes

These names describe scoring behavior rather than listed position:

1. **Balanced Inside-Out Finisher** — moderate volume distributed across the
   rim, short midrange, and both three-point zones, with above-average
   second-chance involvement.
2. **Interior & Putback Big** — nearly 59% of attempts at the rim, minimal
   three-point volume, and the highest putback and second-chance shares.
3. **Transition Slasher & Connector** — moderate-volume players with the
   highest early-offense share, a rim/three balance, and relatively few
   putbacks.
4. **Midrange-Oriented Perimeter Creator** — low rim frequency, the largest
   long-midrange share, and a mix of pull-up-style midrange and perimeter
   attempts.
5. **High-Volume Multi-Level Creator** — the highest overall attempt volume,
   strong three-point and free-throw volume, and meaningful attempts from every
   scoring level.
6. **Paint & Midrange Focal Scorer** — high-volume, free-throw-heavy scoring
   concentrated at the rim and short midrange, with limited three-point use.
7. **Low-Volume Perimeter Spacer** — the lowest overall and free-throw volume,
   with roughly two-thirds of attempts coming from corner or above-break threes.

Because these are style labels, an atypical guard can belong to an
interior-oriented group and a shooting big can belong to a perimeter group.
Height and defensive assignment remain separate matchup descriptors.

## Running

From this directory:

```bash
uv run --with numpy --with pandas --with scikit-learn \
  python scripts/wnba_archetypes_2026.py
```

The public PBP Stats shot endpoint throttles burst traffic and silently caps an
unpartitioned response at 500 shots. The script therefore uses resumable
per-player caches, sequential 1.5-second request pacing, jittered retry backoff,
and quarter/OT partitioning for capped players. A fully cached run makes no API
requests and reproduces the same features, assignments, profiles, and
diagnostics. PCA coordinates may differ at floating-point roundoff scale across
different BLAS builds; PCA is used only for visualization.
